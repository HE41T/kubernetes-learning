# บทที่ 3: การโต้ตอบกับ Kubernetes (Interacting with Kubernetes)

ในฐานะนักพัฒนาแอปพลิเคชัน คุณจะต้องโต้ตอบกับคลัสเตอร์เพื่อจัดการ Object ต่าง ๆ  
ทุกการเรียกใช้งานจะถูกรับและประมวลผลโดย **API server**  
ซึ่งสามารถทำได้หลายวิธี เช่น ผ่าน **Dashboard**, เครื่องมือบรรทัดคำสั่งอย่าง **kubectl** หรือส่งคำขอ HTTPS โดยตรงไปยัง API endpoints

> สำหรับการสอบ จะไม่มีการทดสอบการใช้งานผ่าน UI (Dashboard)  
> เครื่องมือเดียวที่คุณต้องใช้คือ **kubectl**

---

## พื้นฐานของ API (API Primitives and Objects)

**Primitives** คือหน่วยพื้นฐานในการสร้างและรันแอปพลิเคชันบน Kubernetes เช่น Pod, Deployment และ Service  

- เปรียบเทียบกับ **OOP (Object-Oriented Programming):**
  - Primitive ≈ Class (พิมพ์เขียวของคุณสมบัติและพฤติกรรม)
  - Object ≈ Instance (อินสแตนซ์ที่ถูกสร้างจริง มีสถานะเป็นของตัวเอง)
- ทุก Object จะมี **UID (Unique Identifier)** อัตโนมัติ เพื่อแยกแยะแต่ละ Object

---

## โครงสร้างของ Object

ทุก Object ใช้ไฟล์ **YAML** เป็นหลักในการกำหนดค่า (Manifest) ประกอบด้วย:

- `apiVersion`: เวอร์ชันของ API ที่ใช้ตรวจสอบความถูกต้อง
- `kind`: ประเภทของ Primitive (เช่น Pod หรือ Service)
- `metadata`: ข้อมูลระดับสูง เช่น ชื่อ (Name), Namespace, Label
- `spec (Specification)`: การประกาศ "สถานะที่ต้องการ" เช่น อิมเมจที่ใช้, ค่าสภาพแวดล้อม
- `status`: สถานะปัจจุบันของ Object (Kubernetes จะปรับให้ตรงกับ spec)
