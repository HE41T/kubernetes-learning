# ภาคที่ 2: การออกแบบและสร้างแอปพลิเคชัน (Application Design and Build)

ขอบเขตของเนื้อหาเรื่อง "การออกแบบและสร้างแอปพลิเคชัน" จะสรุปหัวข้อพื้นฐานทั้งหมดที่สำคัญต่อการออกแบบกระบวนการหรือแอปพลิเคชัน โดยมีวัตถุประสงค์เพื่อนำไปปฏิบัติการภายใน Kubernetes Pod

บทต่าง ๆ ต่อจากนี้จะครอบคลุมแนวคิดดังต่อไปนี้:

- **บทที่ 4** อธิบายคำศัพท์พื้นฐานเกี่ยวกับคอนเทนเนอร์ เนื้อหาจะใช้ Docker Engine ในการแนะนำคำสั่งสำหรับการนิยาม, การสร้าง (Build), การรัน และการแก้ไขคอนเทนเนอร์อิมเมจ
- **บทที่ 5** นำคอนเทนเนอร์อิมเมจที่มีอยู่มารันใน Pod ซึ่งเป็นหน่วยพื้นฐาน (Primitive) ที่สำคัญสำหรับการรันแอปพลิเคชันใน Kubernetes ภายใต้ Namespace
- **บทที่ 6** กล่าวถึงการออกแบบภาระงานแบบ Batch (Batch workload) และภาระงานที่ต้องรันตามระยะเวลาที่กำหนด (Periodically executed workload) ใน Kubernetes
- **บทที่ 7** อธิบายวิธีแชร์ข้อมูลระหว่างคอนเทนเนอร์ที่รันอยู่ใน Pod เดียวกันโดยใช้ Ephemeral Volumes และอธิบายวิธีจัดเก็บข้อมูลระยะยาวด้วย Persistent Volumes
- **บทที่ 8** แสดงกรณีศึกษาในการรันคอนเทนเนอร์หลายตัวใน Pod เดียว และวิธีปรับใช้ด้วยรูปแบบการออกแบบ (Design patterns) ที่เป็นมาตรฐาน
- **บทที่ 9** แนะนำวิธีการกำหนด Labels และ Annotations ให้กับออบเจกต์ หลังจากอ่านบทนี้คุณจะเข้าใจความสำคัญของ Labels ในการสืบค้น, จัดเรียง และกรองออบเจกต์ ส่วน Annotations จะเป็นการเพิ่มข้อมูลเมตาที่อ่านได้โดยมนุษย์เท่านั้นให้กับออบเจกต์

## บทที่ 4: คอนเทนเนอร์ (Containers)

Kubernetes คือเครื่องมือจัดการคอนเทนเนอร์ (Orchestrator) ที่ใช้ Container runtime เพื่อสร้างอินสแตนซ์ของคอนเทนเนอร์ภายใน Pod คลัสเตอร์ Kubernetes จำนวนมากในเวอร์ชัน 1.24 หรือใหม่กว่าจะใช้ Container runtime ที่ชื่อว่า containerd

### Container runtime ที่ใช้บนโหนดของ Kubernetes:

คุณสามารถดึงข้อมูลเกี่ยวกับ Container runtime ที่ใช้บนโหนดใดก็ได้ในคลัสเตอร์ โดยดูที่คอลัมน์ CONTAINER-RUNTIME จากผลลัพธ์ของคำสั่ง `kubectl get nodes -o wide` และสามารถตรวจสอบเอกสารของ Kubernetes เพื่อเรียนรู้เพิ่มเติมเกี่ยวกับการกำหนดค่า Container runtime สำหรับคลัสเตอร์

สำหรับการสอบ คุณถูกคาดหวังให้เข้าใจแง่มุมในทางปฏิบัติของการนิยาม, การสร้าง และการเผยแพร่อิมเมจคอนเทนเนอร์ ซึ่งบทนี้จะครอบคลุมเนื้อหาดังกล่าว นอกจากนี้เราจะแตะถึงเรื่องการรันคอนเทนเนอร์อิมเมจภายในคอนเทนเนอร์ด้วย สำหรับการปฏิบัติการทั้งหมดนี้ เราจะใช้ Docker Engine เป็นตัวอย่าง แม้ว่าฟังก์ชันการทำงานที่คล้ายกันจะมีให้ในซอฟต์แวร์ตัวอื่น ๆ ก็ตาม

### คำศัพท์เกี่ยวกับคอนเทนเนอร์ (Container Terminology)

คอนเทนเนอร์จะทำการรวม (Package) แอปพลิเคชันให้เป็นหน่วยซอฟต์แวร์เดียว ซึ่งรวมถึงสภาพแวดล้อมที่ใช้รัน (Runtime environment) และการกำหนดค่า (Configuration) โดยปกติจะประกอบด้วยระบบปฏิบัติการ, ซอร์สโค้ดหรือไฟล์ไบนารีของแอปพลิเคชัน, ไลบรารีที่จำเป็น (Dependencies) และเครื่องมือระบบอื่น ๆ เป้าหมายที่ประกาศไว้ของคอนเทนเนอร์คือการแยกสภาพแวดล้อมที่ใช้รันออกจากแอปพลิเคชัน เพื่อหลีกเลี่ยงปัญหา "แต่มันรันในเครื่องผมได้นะ"

- **Container runtime engine**: คือส่วนประกอบซอฟต์แวร์ที่สามารถรันคอนเทนเนอร์บนระบบปฏิบัติการโฮสต์ได้ ตัวอย่างเช่น Docker Engine หรือ containerd
- **Container orchestrator**: ใช้ Container runtime engine เพื่อสร้างคอนเทนเนอร์ พร้อมกับเพิ่มคุณสมบัติที่ซับซ้อน เช่น การขยายระบบ (Scalability) และระบบเครือข่ายสำหรับภาระงาน Kubernetes คือตัวอย่างหนึ่งของเครื่องมือนี้ ส่วนเครื่องมืออื่น ๆ เช่น Nomad ก็สามารถจัดตารางงาน (Scheduling) ให้กับภาระงานต่าง ๆ รวมถึงคอนเทนเนอร์ด้วย
- **Containerization**: กระบวนการรวมแอปพลิเคชันเข้าเป็นคอนเทนเนอร์ ทำงานตามชุดคำสั่งที่นิยามไว้ในไฟล์คอนเทนเนอร์ (หรือที่ชุมชน Docker เรียกว่า Dockerfile) ผลลัพธ์ที่ได้คือ Container image
- **Container registry**: แหล่งสำหรับเผยแพร่อิมเมจเพื่อให้ผู้อื่นนำไปใช้งาน เช่น Docker Hub เป็นแหล่งหลักสำหรับการใช้งานสาธารณะ นอกจากนี้ยังมีแหล่งอื่น ๆ เช่น GCR และ Quay

### การสร้างคอนเทนเนอร์แอปพลิเคชัน Java (Containerizing a Java-Based Application)

สมมติว่าเราต้องการทำคอนเทนเนอร์สำหรับเว็บแอปพลิเคชันที่เขียนด้วย Java โดยใช้เฟรมเวิร์ก Spring Boot และต้องการควบคุมพฤติกรรมผ่าน Environment variables เช่น URL และข้อมูลประจำตัวเพื่อเชื่อมต่อกับฐานข้อมูล

1. **การเขียน Dockerfile**: เป็นไฟล์ข้อความธรรมดาที่ระบุชุดคำสั่ง เช่น FROM (กำหนดอิมเมจฐาน), WORKDIR (ตั้งค่าไดเรกทอรีทำงาน), COPY (คัดลอกไฟล์แอป), ENTRYPOINT (คำสั่งเริ่มต้นเมื่อรันคอนเทนเนอร์) และ EXPOSE (ระบุพอร์ตเครือข่าย)

2. **การสร้างอิมเมจ (Building)**: ใช้คำสั่ง `docker build -t [ชื่ออิมเมจ]:[tag] .` โดยเครื่องหมายจุด ( . ) หมายถึงไดเรกทอรีปัจจุบันที่เป็น Context ของการสร้าง

3. **การรัน (Running)**: ใช้คำสั่ง `docker run -d -p 8080:8080 [ชื่ออิมเมจ]` เพื่อรันแอปในแบบ Background (-d) และส่งต่อพอร์ต (-p) จากเครื่องโฮสต์ไปยังคอนเทนเนอร์

4. **การโต้ตอบ (Interacting)**:
   - ใช้ `docker logs [ID]` เพื่อตรวจสอบข้อความ Log ของแอปพลิเคชัน
   - ใช้ `docker exec -it [ID] bash` เพื่อเปิด Shell เข้าไปสำรวจระบบไฟล์ภายในคอนเทนเนอร์

5. **การเผยแพร่ (Publishing)**: ต้องใช้คำสั่ง `docker tag` เพื่อเพิ่มชื่อ Username หรือ Hostname นำหน้าชื่ออิมเมจก่อนจะใช้คำสั่ง `docker push` เพื่อส่งอิมเมจไปยัง Registry

6. **การบันทึกและโหลด (Saving and Loading)**: สามารถใช้คำสั่ง `docker save` เพื่อเก็บอิมเมจเป็นไฟล์ .tar และใช้ `docker load` เพื่อนำอิมเมจกลับเข้าสู่ Cache จากไฟล์ได้
