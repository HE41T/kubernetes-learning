# บทที่ 5: Pods และ Namespaces

หน่วยพื้นฐานที่สำคัญที่สุดใน Kubernetes API คือ Pod ซึ่งช่วยให้คุณรันแอปพลิเคชันในคอนเทนเนอร์ได้ ในทางปฏิบัติคุณมักจะพบการจับคู่แบบหนึ่งต่อหนึ่งระหว่าง Pod และคอนเทนเนอร์ อย่างไรก็ตาม กรณีศึกษาในบทที่ 8 จะแสดงให้เห็นประโยชน์ของการประกาศคอนเทนเนอร์มากกว่าหนึ่งตัวใน Pod เดียว

นอกจากรันคอนเทนเนอร์แล้ว Pod ยังสามารถเข้าถึงบริการอื่น ๆ เช่น พื้นที่จัดเก็บข้อมูล และข้อมูลการกำหนดค่าได้ ดังนั้นให้คิดว่า Pod คือ "ตัวห่อหุ้ม" สำหรับการรันคอนเทนเนอร์ พร้อมกับความสามารถในการผสมผสานคุณสมบัติเฉพาะด้านของ Kubernetes เข้าไปด้วย

---

## การทำงานกับ Pod (Working with Pods)

ในบทนี้เราจะดูการทำงานกับ Pod ที่รันคอนเทนเนอร์เพียงตัวเดียว โดยใช้ทั้งวิธีแบบคำสั่ง (Imperative) และแบบประกาศเป้าหมาย (Declarative)

### การสร้าง Pod:

ในการนิยาม Pod ต้องระบุอิมเมจสำหรับทุกคอนเทนเนอร์ เมื่อสร้างออบเจกต์ขึ้นมา Scheduler จะกำหนด Pod ไปยังโหนด และ Container runtime engine จะตรวจสอบว่ามีอิมเมจอยู่บนโหนดนั้นหรือไม่ หากไม่มีจะดาวน์โหลดจาก Registry (โดยเริ่มต้นคือ Docker Hub)

- **คำสั่ง kubectl run**: เป็นจุดเริ่มต้นหลักสำหรับการสร้าง Pod แบบ Imperative แฟล็กที่สำคัญที่ควรจำคือ:
    - `--image`: ระบุอิมเมจ
    - `--port`: ระบุพอร์ตที่คอนเทนเนอร์ใช้งาน
    - `--env`: ตั้งค่าสภาพแวดล้อม (Environment variables)
    - `--labels`: กำหนดป้ายกำกับ
    - `--rm`: ลบ Pod ทันทีหลังจากงานเสร็จสิ้น (เหมาะสำหรับ Pod ชั่วคราว)

- **การสร้างจากไฟล์ YAML**: นักพัฒนามักใช้การประกาศผ่านไฟล์ Manifest โดยระบุ `apiVersion: v1`, `kind: Pod`, `metadata` (ชื่อและป้ายกำกับ) และ `spec` (รายละเอียดคอนเทนเนอร์) จากนั้นสั่งรันด้วย `kubectl apply -f [ชื่อไฟล์]`

## วงจรชีวิตของ Pod (Pod Life Cycle Phases)

สถานะของ Pod อาจไม่แสดงเป็น Running ทันทีหลังจากสร้าง เนื่องจากต้องใช้เวลาดึงอิมเมจและเริ่มคอนเทนเนอร์ โดยมีระยะต่าง ๆ ดังนี้:

- **Pending**: ระบบรับ Pod แล้ว แต่อิมเมจคอนเทนเนอร์อย่างน้อยหนึ่งตัวยังสร้างไม่เสร็จ
- **Running**: คอนเทนเนอร์อย่างน้อยหนึ่งตัวกำลังทำงานอยู่ หรืออยู่ในกระบวนการเริ่มการทำงานใหม่
- **Succeeded**: คอนเทนเนอร์ทั้งหมดใน Pod สิ้นสุดการทำงานอย่างสำเร็จสมบูรณ์
- **Failed**: คอนเทนเนอร์ใน Pod สิ้นสุดการทำงาน และมีอย่างน้อยหนึ่งตัวที่ล้มเหลวพร้อมข้อผิดพลาด
- **Unknown**: ไม่สามารถระบุสถานะของ Pod ได้

## การตรวจสอบและเข้าถึง Pod

- **การแสดงรายละเอียด**: คำสั่ง `kubectl get pods` ให้ข้อมูลภาพรวม แต่ถ้าต้องการดูรายละเอียดเชิงลึก (เช่น เหตุการณ์การทำงานหรือปัญหาการจองโหนด) ให้ใช้ `kubectl describe pods [ชื่อ]`

- **การเข้าถึง Log**: ใช้ `kubectl logs [ชื่อ]` หากต้องการดู Log แบบ Real-time ให้เพิ่มแฟล็ก `-f` และหากต้องการดู Log ของคอนเทนเนอร์ก่อนหน้าที่เพิ่งรีสตาร์ทไป ให้ใช้แฟล็ก `-p`

- **การสั่งงานภายใน**: ใช้ `kubectl exec -it [ชื่อ] -- /bin/sh` เพื่อเปิด Shell โต้ตอบกับคอนเทนเนอร์ หรือใช้ `kubectl exec [ชื่อ] -- [คำสั่ง]` เพื่อรันคำสั่งเดียว

## ระบบเครือข่าย (Networking)

ทุก Pod จะได้รับ IP Address เฉพาะตัวเมื่อถูกสร้างขึ้น ซึ่งไม่ซ้ำกันในทุกโหนดและทุก Namespace อย่างไรก็ตาม IP นี้ไม่ถือว่ามีความเสถียร เนื่องจากเมื่อรีสตาร์ท Pod จะได้รับ IP ใหม่เสมอ ดังนั้นหากต้องการการสื่อสารระหว่างแอปพลิเคชันที่คงที่ จำเป็นต้องใช้แนวคิดเรื่อง Service แทน

---

## การกำหนดค่า Pod (Configuring Pods)

- **Environment Variables**: ใช้เพื่อทำให้พฤติกรรมของแอปพลิเคชันสามารถกำหนดค่าได้โดยไม่ต้องสร้างอิมเมจใหม่ทุกครั้งสำหรับแต่ละสภาพแวดล้อม (ตามหลัก Twelve-Factor App) โดยกำหนดในส่วน `env` ภายในไฟล์ YAML

- **Command และ Arguments**: ใน Pod definition คุณสามารถเขียนทับคำสั่งเริ่มต้นของอิมเมจได้:
    - แอตทริบิวต์ `command` จะเขียนทับ ENTRYPOINT ของอิมเมจ
    - แอตทริบิวต์ `args` จะเขียนทับ CMD ของอิมเมจ

## การใช้งาน Namespaces

Namespace คือโครงสร้างใน API ที่ใช้เพื่อหลีกเลี่ยงการตั้งชื่อซ้ำซ้อน และใช้เป็นขอบเขต (Scope) สำหรับชื่อออบเจกต์ ช่วยในการแยกออบเจกต์ตามทีมหรือความรับผิดชอบ

- `kubectl get namespaces`: แสดงรายการ Namespace ทั้งหมด (เริ่มต้นจะมี default, kube-system เป็นต้น)
- **การระบุ Namespace**: ใช้แฟล็ก `--namespace` หรือ `-n` ในคำสั่งเพื่อจัดการออบเจกต์ใน Namespace นั้น ๆ
- **การตั้งค่าถาวร**: หากไม่อยากพิมพ์แฟล็กทุกครั้ง สามารถตั้งค่า Namespace หลักได้ด้วยคำสั่ง `kubectl config set-context --current --namespace=[ชื่อ]`
- **การลบ**: การลบ Namespace จะส่งผลแบบ Cascading คือออบเจกต์ทั้งหมดที่อยู่ภายใน Namespace นั้นจะถูกลบไปด้วยโดยอัตโนมัติ
